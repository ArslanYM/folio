# How to Use DESIGN.md to Generate High-End UIs with AI

Turn your extracted or curated `DESIGN.md` specification into production-ready, pixel-perfect user interfaces using **Cursor**, **Claude Code**, **GitHub Copilot**, **Windsurf**, or **v0**.

---

## 🎯 The Core Problem with AI UI Generation

When you ask an AI coding assistant to *"build a modern dashboard"* or *"create a SaaS landing page"*, it almost always falls back on generic defaults:
- **Cookie-cutter color schemes:** Slate/Indigo or Zinc/Purple palettes with flat contrast.
- **Inconsistent tokens:** Random hex codes invented on the fly (`#3b82f6`, `#1f2937`).
- **Unrefined typography:** Default system fonts without intentional scale, leading, or letter-spacing.
- **Generic components:** Boxy cards, harsh shadows, and zero brand personality.

A **`DESIGN.md`** file provides the concrete visual DNA that transforms generic AI code into bespoke, agency-quality software.

## Step 1: Install the Tokens in Your Project

Every `DESIGN.md` generated by Swatchbook includes a deterministic **`## Quick Start`** section. Copy and paste this directly into your styles:

### Tailwind CSS v4 (Recommended)

In `app/globals.css` or your main stylesheet:

```css
@import "tailwindcss";

@theme inline {
  --color-canvas: #0E0D0B;
  --color-surface: #17150F;
  --color-raised: #211E17;
  --color-accent: #C8F23D;
  --color-accent-foreground: #0E0D0B;
  --color-foreground: #F2EDE2;
  --color-muted: #8F887A;
  --color-border: #2E2A21;

  --font-display: var(--font-bricolage), sans-serif;
  --font-sans: var(--font-geist-sans), sans-serif;
  --font-mono: var(--font-geist-mono), monospace;

  --radius-sm: 4px;
  --radius-md: 8px;
  --radius-lg: 12px;
}
```

### Tailwind CSS v3

In `tailwind.config.ts`:

```typescript
export default {
  theme: {
    extend: {
      colors: {
        canvas: "var(--color-canvas)",
        surface: "var(--color-surface)",
        raised: "var(--color-raised)",
        accent: {
          DEFAULT: "var(--color-accent)",
          foreground: "var(--color-accent-foreground)",
        },
        foreground: "var(--color-foreground)",
        muted: "var(--color-muted)",
        border: "var(--color-border)",
      },
    },
  },
};
```

## Step 2: Configure Your AI Tool

Place `DESIGN.md` in the root of your project repository, then configure your tool:

### 1. Cursor (Composer & Agent Mode)

#### Method A: Direct File Reference
In Cursor Composer (`Cmd+I` / `Ctrl+I`) or Chat (`Cmd+L` / `Ctrl+L`), reference the spec with `@`:

```text
@DESIGN.md Build the navigation header with desktop links, mobile drawer, and CTA.
```

#### Method B: Project Rule (`.cursor/rules/design.mdc`)
Create a persistent rule in `.cursor/rules/design.mdc`:

```markdown
---
description: Design System & UI Styling Rules
globs: "**/*.{tsx,jsx,css,html}"
alwaysApply: true
---
Strictly follow the design system specifications defined in `DESIGN.md`.

Rules:
1. Never invent arbitrary hex codes or unapproved Tailwind colors (no `bg-blue-600`, no `#2563EB`).
2. Always use the semantic tokens defined in DESIGN.md: `bg-canvas`, `bg-surface`, `text-foreground`, `text-accent`, `border-border`.
3. Follow the typography hierarchy, font families, and letter spacing in Section 3.
4. Follow the component recipes in Section 7 (button variants, card styles, input focus states).
5. Strictly adhere to the Do's and Don'ts in Section 15.
```

---

### 2. Claude Code (CLI)

Add the instruction to your `CLAUDE.md` in the repo root:

```markdown
# Project Guidelines

## Design System & Frontend Styling
All UI components MUST adhere strictly to the design system in `DESIGN.md`.
- Use semantic CSS variables/tokens (`bg-surface`, `text-accent`, `border-border`).
- Do not introduce arbitrary utility colors or default Tailwind palettes.
- Verify contrast and adhere to the Do's and Don'ts in `DESIGN.md`.
```

Then prompt Claude Code in your terminal:
```bash
claude "Inspect DESIGN.md and build the Pricing component in components/pricing.tsx"
```

## Step 3: The 4-Part Golden Prompt Formula

For best results when prompting AI for individual components, use this 4-part structure:

```text
1. ROLE & SPEC CONTEXT
You are a senior frontend engineer. Strictly follow the design tokens and recipes in `DESIGN.md`.

2. COMPONENT SCOPE & BEHAVIOR
Build a responsive pricing section featuring:
- Monthly / Annual billing toggle (15% discount badge on annual)
- 3 tiers (Starter, Pro [highlighted with accent glow], Enterprise)
- Feature checkmark list with clear spacing
- Action buttons for each tier

3. TOKEN MAPPING
- Section background: var(--color-canvas)
- Standard cards: var(--color-surface) with 1px border-border
- Featured card: Subtle highlight with border-accent/40 and a pill badge
- Typography: Display font for prices and tier names; sans-serif for descriptions
- Border radius: var(--radius-lg)

4. ANTI-HALLUCINATION GUARDRAILS
- DO NOT use generic Tailwind colors (no blue-500, gray-700, slate-900).
- Adhere strictly to Section 15 (Do's and Don'ts) in DESIGN.md.
```

## Step 4: Component-by-Component Workflow

Avoid asking the AI to *"generate the entire website at once"*. Instead, generate section by section for unmatched polish:

| Order | Component | What to emphasize from `DESIGN.md` |
| --- | --- | --- |
| **1** | **Navbar** | Sticky backdrop-blur, brand monogram, active link states |
| **2** | **Hero** | Pill badge, headline scale (`text-4xl sm:text-6xl`), dual CTAs |
| **3** | **Feature Grid** | Card border tokens, icon containers, elevation shadows |
| **4** | **Pricing / Social Proof** | High-contrast tier cards, accent ring highlights, testimonials |
| **5** | **Footer** | Muted typography, subtle dividers, external link icons |

---

## 💡 Pro Tips for Maximum Visual Fidelity

1. **Keep the negative constraints:** AI models love adding gradients and extra saturated accents. Remind the model: *"Use accent color ONLY for primary interactions and active states, never as large background fills."*
2. **Lock down border colors:** In dark mode, borders should be subtle (`#2E2A21` or `rgba(255,255,255,0.08)`), not standard gray. Point the model directly to your `--color-border` token.
3. **Inspect the live preview:** When viewing a template on Swatchbook (`/templates/<slug>`), switch between **Preview**, **Spec**, and **Type Specimen** to see how the tokens render before prompting.
4. **Use deterministic Quick Start:** Always paste the Quick Start tokens into your CSS first so your IDE autocomplete suggests the exact token classes (`bg-canvas`, `text-accent`).
